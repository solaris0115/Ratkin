# Ratkin RimWorld 1.7 CSharp Compatibility Static Review

검토일: 2026-10-13. 기준 설치본: RimWorld 1.7.4976 rev1043.

## 범위

- `Project/1.6/Source/` 전체 C#와 기존 프로젝트, 1.6/1.7 디컴파일 API 비교.
- 1.7 프로젝트는 기존 소스를 링크하며 `RIMWORLD_1_7`로 변경된 생성·연사 진입점을 분리한다.
- 테스트, 게임 실행, 빌드, DLL 생성은 수행하지 않았다. Roslyn의 구문·의미 진단만 사용했다.

## 수정

| 영역 | 확인한 문제 | 처리 |
|---|---|---|
| 실행 기반 | 기존 net472·Unity Managed 참조로 1.7을 대상으로 할 수 없음 | net10.0·설치본 루트 참조 프로젝트 추가, 출력 분리 |
| 사제 합류 | 1.7 `RunInt`가 `GeneratePawn_NewTemp(Map)`를 호출하여 기존 override를 우회 | 새 진입점을 사제 생성에 연결, 맵 전달, 영입 가능 보장, 성인만 예배 능력 부여 |
| 펄스 라이플 | 버스트 처리 복제본에 원본의 전투 대상 알림이 누락 | 1.7은 게임 버스트 처리 유지, 간격 getter만 모드·유니크 특성에 맞게 변경 |
| 유랑단 | `PlanetTile`을 `int`로 전달해 계층 정보 소실 | 병력·유랑민·짐꾼 생성 및 방문 연도 처리에 `PlanetTile` 유지 |
| 합류·순례·터널 | 생성 요청에 도착 위치가 없어 위치별 생성 조건을 적용하지 못함 | 해당 맵 타일 전달 |
| 용병 | 기본 생성자를 사용해 요청 구조체의 성장 단계·나이 특성 기본값이 0 | 정상 생성자 사용 |
| 체인소드 | 원본 피해 결과와 병합 결과가 같은 객체여서 순회 중 부위 목록이 늘어남 | 복사본 순회, 추가 피해는 정상 `TakeDamage` 경로 사용 |
| 후속 습격 | 적대 팩션이면 생성 실패에도 성공 집계, null 팩션 접근 가능 | 실패 즉시 반환, silent 처리·최근 습격 팩션 갱신, 팩션별 전략 가중치 적용 |

## 정적 검토 결과

- 개발 기능 포함 153개, 배포 기능 150개 C# 구문 트리 대상.
- 1.7 게임·엔진 DLL 메타데이터와 .NET 10 참조 팩을 사용한다. 모드 DLL을 생성하거나 코드를 실행하지 않는다.
- Harmony 패치 메서드·속성의 실제 이름과 overload를 메타데이터로 확인했다. 사제·유전자·정보창 등의 비공개 필드도 디컴파일 소스와 대조했다.
- 오류 0개. 경고 1종: Harmony의 `System.Runtime` 8.0 참조를 대상 10.0 참조에 연결하는 CS1701. 동일 경고 중복은 집계에서 묶었다.
- 기존 워해머·벽화·매의 눈 보류 주석/전처리 상태를 유지한다.

## 한계

- 이 결과는 C# 정적 호환성 검토이며 전체 모드의 1.7 구동 성공 판정이 아니다.
- `About.xml` 지원 버전과 `LoadFolders.xml`은 아직 1.7을 선언하지 않는다. 이 작업은 C# 범위여서 수정하지 않았다.
- 설치된 HAR에는 1.7 전용 폴더가 없다. HAR의 1.7 런타임 및 리플렉션 확장 호환성은 확인하지 못했다.
- 실제 로딩, 세이브, 전투·퀘스트·렌더링 동작은 사용자 요청대로 테스트하지 않았다.
